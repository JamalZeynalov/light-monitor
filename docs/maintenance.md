# Зміни й обслуговування

## Змінити тексти

У `worker.js` редагуйте `POWER_ON_MESSAGES` і `POWER_OFF_MESSAGES`. Не залишайте списки порожніми. Одна подія має один варіант тексту для всіх отримувачів і повторних спроб. Ручний `/test` вибирає з обох списків та додає `🧪 ТЕСТ`.

Після редагування відкрийте Cloudflare → Worker → **Edit code**, вставте весь оновлений файл і натисніть **Deploy**. Локальний файл не завантажується у Cloudflare автоматично. Плату для зміни повідомлень перепрошивати не потрібно.

## Інтервали й отримувачі

`OFFLINE_AFTER_SECONDS = 120` у Worker задає поріг відсутності сигналу. `HEARTBEAT_MS = 60000` у прошивці задає інтервал надсилання. Cron працює раз на хвилину, тому 120 секунд не є гарантією доставки рівно через дві хвилини.

Список чатів змінюється в `TELEGRAM_CHAT_IDS` у Cloudflare. Максимум 10 різних ID. Для нової плати в іншому будинку створіть окремий Worker і D1; поточна база зберігає стан лише одного пристрою.

Новий `DEVICE_SECRET` потрібно зберегти в Cloudflare, локальному `.env` і `config.h`, а потім перепрошити плату. Новий пароль Wi-Fi вводиться через портал без перепрошивання.

## Перевірка коду

Для тестів Worker потрібен **Node.js 24 або новіший**. У корені проєкту виконайте:

```bash
npm test
```

Залежностей npm немає. Тести використовують локальну SQLite як заміну D1 та підміняють Telegram: повідомлення нікому не надсилаються. Вони перевіряють поріг 120 секунд, зміни стану, авторизацію, порядок доставок, повторні спроби та відсутність технічних сповіщень у чаті.

Прошивку перевіряйте через **Verify** в Arduino IDE. Перевірка сервера не замінює компіляцію або фізичний тест плати.

## Що зберігається в базі

`monitor` містить поточний стан, `events` історію подій, `deliveries` результат доставки кожному чату. Невдалі доставки повторюються. Якщо Telegram прийняв повідомлення, але відповідь загубилася, повторна спроба інколи може створити дублікат.

Історія не очищується автоматично. Стежте за розміром D1 та квотами. Для довготривалого використання можна окремо додати політику очищення старих доставлених подій.

Список довірених CA лежить у `trusted_roots.h`. Джерела вказані в коментарі; після зміни центрів сертифікації сервера може знадобитися оновлення цього файлу й прошивки.
